# Управление кондиционером из Telegram

Бот шлёт ИК-команды кондиционеру Bergen BER18AAC-G18/I (протокол Gree, пульт YAW1F)
через ESP32 с прошивкой Tasmota. Плата стоит дома, бот и брокер MQTT — на внешнем сервере.
Описание железа — в [desc.txt](desc.txt).

## Что важно понимать

**ИК-канал односторонний.** Кондиционер не сообщает о себе ничего. Статус в меню — это
последняя успешно отправленная команда, а не реальное состояние устройства. Если кондиционер
выключили обычным пультом, бот об этом не узнает.

**Gree передаёт состояние целиком.** Каждая ИК-команда переписывает все параметры сразу,
поэтому бот хранит полный набор и шлёт его весь при каждой отправке — иначе погас бы дисплей
и сбросился режим.

Что бот всё-таки знает: жива ли плата (`tele/<топик>/LWT`) и приняла ли она команду
(`stat/<топик>/RESULT`). При проблеме состояние **не меняется** и приходит честное
предупреждение. Каждая команда для надёжности публикуется дважды.

## Меню

```
/menu или /start

Кондиционер
Питание: 🔴 Выключен
Режим: ❄️ Охлаждение
Температура: 24°C
Плата: 🟢 на связи

[🟢 Включить]
[✅ ❄️ Охлаждение] [🔥 Нагрев]
[🔽] [24°C] [🔼]
```

Это одна панель на весь диалог: любое нажатие перерисовывает то же самое сообщение через
`editMessageText`, новых сообщений в чате не появляется. `/menu` и `/start` отправляют новую
панель — редактировать там пока нечего.

Стрелки меняют температуру по градусу в пределах 17–30. На границе диапазона ИК-команда
не отправляется, панель просто дописывает строку «дальше некуда». Средняя кнопка — индикатор,
она ничего не делает.

Смена режима или температуры при выключенном кондиционере только запоминается — ИК-команда
не отправляется, новые настройки применятся при включении.

Результат действия показывается припиской внизу той же панели («сохранено», «команда не ушла»),
а не отдельным сообщением.

Скорость вентилятора и подсветка дисплея зафиксированы (`Auto` и `On`) и в меню не выводятся,
но уходят в каждый payload.

## Развёртывание

### 1. Настройки

```bash
cp .env.example .env
```

Заполнить `API_TOKEN` (от [@BotFather](https://t.me/BotFather)), `ALLOWED_CHAT_IDS`
(свой id узнать у [@userinfobot](https://t.me/userinfobot), несколько — через запятую)
и `MQTT_PASSWORD`. Пустой белый список означал бы «можно всем», поэтому бот с ним не запустится.

### 2. Пользователи брокера

```bash
# -c СОЗДАЁТ файл, поэтому только в первой команде
docker compose run --rm --entrypoint mosquitto_passwd mosquitto \
    -c -b /mosquitto/config/passwd tasmota 'ПАРОЛЬ_ПЛАТЫ'
# второй пользователь — БЕЗ -c, иначе первый будет затёрт
docker compose run --rm --entrypoint mosquitto_passwd mosquitto \
    -b /mosquitto/config/passwd bot 'ПАРОЛЬ_БОТА'
chmod 0700 mosquitto/config/passwd
```

Mosquitto 2.x отказывается читать файл паролей с правами шире `0700`. В git файл не попадает.

### 3. Запуск

```bash
sudo ufw allow 1883/tcp        # плата подключается снаружи
docker compose up -d --build
docker compose logs -f bot
```

### 4. Tasmota

В консоли платы (`http://192.168.0.200` → Consoles → Console):

```
Backlog MqttHost <IP_СЕРВЕРА>; MqttPort 1883; MqttUser tasmota; MqttPassword ПАРОЛЬ_ПЛАТЫ; Topic tasmota_A3CA74; MqttClient tasmota_A3CA74
```

Проверить:

| Команда | Ожидается | Почему важно |
|---|---|---|
| `Status 6` | `MqttHost` = ваш сервер, `MqttCount` растёт медленно | быстрый рост = флаппинг: неверный пароль или занятый ClientId |
| `FullTopic` | `%prefix%/%topic%/` | при другом значении бот не найдёт свои топики |
| `SetOption4` | `0` | при `1` ответ уйдёт в `stat/…/IRHVAC`, и подтверждение отправки сломается |

ClientId платы (`tasmota_A3CA74`) и бота (`MQTT_CLIENT_ID`, по умолчанию `ac_bot`) обязаны
различаться — при совпадении брокер будет по очереди выкидывать обоих.

Проверка с сервера — сразу после подписки должен прилететь retained LWT:

```bash
mosquitto_sub -h <СЕРВЕР> -u bot -P 'ПАРОЛЬ_БОТА' \
    -t 'tele/tasmota_A3CA74/#' -t 'stat/tasmota_A3CA74/#' -v
```

## Безопасность

Порт 1883 открыт в интернет **без TLS**: пароль MQTT и все команды передаются между домом и
сервером открытым текстом. Анонимный доступ запрещён, так что случайный сканер ничего не сделает,
но тот, кто слушает трафик на маршруте, увидит пароль. Это осознанный компромисс.

Закрыть его можно так: включить TLS на 8883 с сертификатом Let's Encrypt на домен сервера,
предварительно проверив командой `SetOption103`, что в сборке Tasmota (release-ir) TLS есть —
он вкомпилирован не всегда.

Токен бота и пароль брокера живут только в `.env`, в git его нет.

## Разработка

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements-dev.txt
./venv/bin/python -m pytest -q
./venv/bin/ruff check .
```

Тестами покрыты слои, работающие без железа: сборка payload, разбор белого списка, файл состояния
с защитой от гонок, шаг температуры с упором в границы и MQTT-слой на подставном клиенте
(публикация дважды, таймаут подтверждения, переподключение при разрыве).

Структура повторяет проект `Cost_accounting_bot`: точка входа
[aiogram_handler.py](aiogram_handler.py), контейнер объектов [init.py](init.py),
[command_manager.py](command_manager.py), класс на команду в [commands/](commands/),
тексты интерфейса в [datafiles/messages/](datafiles/messages/).
