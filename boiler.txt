СИСТЕМА УДАЛЁННОГО УПРАВЛЕНИЯ БОЙЛЕРОМ
Спецификация для разработки клиентского приложения

=====================================================================
1. ЧТО ЭТО ЗА СИСТЕМА
=====================================================================

Электрический накопительный водонагреватель (бойлер) Bosch Tronic 3500 T,
модель TR3501T 50 DERB. Характеристики: 230 В, 1500 Вт, объём 47 литров.

Бойлер включён в обычную розетку через умную Wi-Fi розетку. Управление
сводится к подаче и снятию питания: бойлер настроен так, что при подаче
питания он сразу начинает нагрев с последними заданными настройками.
Никакого другого управления (температура, режимы) через API недоступно —
только "включить питание" и "выключить питание".

Умная розетка: безымянное устройство на платформе Tuya, 16 А / 3680 Вт,
со встроенным измерением потребления (ваттметр). Именно ваттметр даёт
обратную связь о реальном состоянии бойлера.

Цепочка управления:

    Приложение  ->  HTTP API на VPS  ->  облако Tuya  ->  розетка  ->  бойлер

Приложение НИКОГДА не обращается к Tuya напрямую. Оно знает только
про HTTP API на VPS, описанный ниже. Все детали работы с Tuya
(токены, обновление сессии, коды датапоинтов) скрыты внутри сервера.

=====================================================================
2. СЕРВЕРНАЯ ЧАСТЬ (уже реализована)
=====================================================================

Стек: Python, FastAPI, uvicorn, библиотека tuya-device-sharing-sdk.

Авторизация в Tuya сделана через QR-вход из мобильного приложения Tuya
(tuya-device-sharing-sdk с регистрацией приложения Home Assistant).
Аккаунт разработчика Tuya и его пробный период НЕ используются —
это сознательное решение, чтобы система работала бессрочно и бесплатно.
Токен доступа хранится в файле token.json на сервере и обновляется
автоматически. Разработчику приложения об этом знать не нужно.

Сервер слушает 127.0.0.1:8000, наружу выставляется через обратный
прокси (Caddy или nginx) с HTTPS.

=====================================================================
3. HTTP API
=====================================================================

Базовый URL: https://<домен>  (в разработке http://127.0.0.1:8000)

АУТЕНТИФИКАЦИЯ
--------------
Каждый запрос должен содержать заголовок:

    Authorization: Bearer <API_TOKEN>

API_TOKEN — статическая строка, заданная на сервере в переменной
окружения. Это не OAuth, не JWT, срок действия не истекает. Приложение
должно хранить её в защищённом хранилище платформы (Keychain на iOS,
EncryptedSharedPreferences или Keystore на Android), а не в открытом виде.

Ошибки аутентификации:
    401 + {"detail": "Нужен заголовок Authorization"}  — заголовок отсутствует
    401 + {"detail": "Неверный токен"}                 — токен не совпал


GET /status
-----------
Возвращает текущее состояние. Ответ 200:

    {
      "on": true,          bool   — подано ли питание на бойлер
      "watts": 1498.2,     float  — текущая потребляемая мощность, Вт
      "volts": 227.0,      float  — напряжение сети, В
      "amps": 6.5,         float  — ток, А
      "heating": true,     bool   — бойлер реально греет (см. ниже)
      "countdown": 4821    int    — секунд до автовыключения, 0 = таймер не активен
    }

ВАЖНО про разницу "on" и "heating":

    "on"      — состояние реле розетки. Питание подано или нет.
    "heating" — бойлер фактически потребляет мощность (> 100 Вт).

Это РАЗНЫЕ вещи, и именно в этом главная ценность ваттметра.
Возможные комбинации:

    on=false, heating=false — питание снято, бойлер не работает
    on=true,  heating=true  — вода греется, идёт нагрев (~1500 Вт)
    on=true,  heating=false — питание подано, но встроенный термостат
                              бойлера отключил ТЭН: вода уже горячая

Третий случай — самый полезный. Он означает "бойлер готов, вода нагрета".
Приложение должно отображать это отдельным состоянием, а не как ошибку.


POST /on
--------
Подаёт питание на бойлер.

Необязательный query-параметр:
    minutes (int, по умолчанию 0) — через сколько минут выключить автоматически.
    0 означает "без таймера, оставить включённым".

Примеры:
    POST /on             — включить бессрочно
    POST /on?minutes=90  — включить на 90 минут, затем выключить

Ответ 200: {"ok": true}

КРИТИЧЕСКИ ВАЖНО: таймер реализован внутри самой розетки (её встроенная
функция обратного отсчёта), а не на сервере и не в приложении. Поэтому он
сработает, даже если упадёт VPS, пропадёт интернет или разрядится телефон.

Приложение ДОЛЖНО по умолчанию предлагать включение с таймером.
Нагреватель на 1500 Вт, оставленный включённым по забывчивости, — это
и лишний расход, и нежелательный риск. Включение без таймера должно быть
осознанным выбором пользователя, а не значением по умолчанию.


POST /off
---------
Снимает питание и сбрасывает таймер обратного отсчёта.

Ответ 200: {"ok": true}


POST /blink
-----------
Отладочная ручка: включить, подождать, выключить. Блокирует воркер
на время ожидания. В продакшене использовать не следует, приложению
она не нужна.

Параметр: seconds (int, по умолчанию 5)


ОШИБКИ ВЗАИМОДЕЙСТВИЯ С TUYA
----------------------------
    502 + {"detail": "Tuya вернула ошибку: ..."}

Возникает, если облако Tuya недоступно, розетка не в сети или истёк токен.
Приложение должно показывать это как временную проблему связи
и предлагать повторить, а не как поломку системы.

=====================================================================
4. ПОВЕДЕНИЕ, КОТОРОЕ ПРИЛОЖЕНИЕ ДОЛЖНО УЧИТЫВАТЬ
=====================================================================

ЗАДЕРЖКА ПОСЛЕ КОМАНДЫ
Команда идёт через облако Tuya. Состояние обновляется не мгновенно.
После POST /on или /off нужно подождать примерно 1,5–2 секунды
перед запросом GET /status, иначе можно прочитать старое значение.

Рекомендуемый паттерн: сразу после команды показать оптимистичное
состояние в интерфейсе, затем через 2 секунды запросить /status
и синхронизироваться с реальностью.

КЭШИРОВАНИЕ НА СЕРВЕРЕ
GET /status кэшируется сервером на 3 секунды, чтобы не упираться
в лимиты облака Tuya. Кэш автоматически сбрасывается после любой
команды. Опрашивать /status чаще одного раза в 3 секунды бессмысленно.

Разумная частота опроса: раз в 10–30 секунд, когда экран открыт.
В фоне опрашивать не нужно.

ВРЕМЯ НАГРЕВА
47 литров с холодной воды до ~60 °C нагреваются примерно 1,5–2 часа.
Это полезно для подсказок в интерфейсе и для выбора значения таймера
по умолчанию. Разумное значение по умолчанию: 90 минут.

ПОВЕДЕНИЕ ПОСЛЕ ОТКЛЮЧЕНИЯ ЭЛЕКТРИЧЕСТВА
Розетка настроена в режим "last": после восстановления питания она
возвращается в то состояние, в котором была. Это следует учитывать:
после долгого отключения света бойлер может оказаться включённым.

РУЧНОЕ УПРАВЛЕНИЕ
На корпусе розетки есть физическая кнопка, и параллельно работает
штатное приложение Tuya. Состояние может измениться без участия
вашего приложения. Поэтому нельзя считать локальное состояние
источником истины — источник истины всегда GET /status.

=====================================================================
5. РЕКОМЕНДАЦИИ ПО ИНТЕРФЕЙСУ
=====================================================================

Главный экран должен отвечать на один вопрос: "горячая вода есть?"

Предлагаемые состояния:

    Выключен          on=false
    Греется           on=true,  heating=true
    Вода готова       on=true,  heating=false
    Нет связи         ошибка 502 или таймаут

Полезно показывать:
    - текущую мощность в ваттах, когда идёт нагрев
    - оставшееся время таймера в понятном виде ("выключится через 1 ч 20 мин")
    - время с момента включения

Основное действие: включить на заданное время. Хорошо работают
пресеты (30 / 60 / 90 минут) плюс возможность задать своё значение.

Стоит предусмотреть подтверждение при включении без таймера.

=====================================================================
6. СПРАВОЧНО: ВНУТРЕННИЕ КОДЫ TUYA
=====================================================================

Приложению это не нужно, но полезно для понимания и отладки сервера.
Розетка отдаёт следующие датапоинты:

    switch_1        bool   реле
    countdown_1     int    таймер обратного отсчёта, секунды
    cur_power       int    мощность в ДЕСЯТЫХ долях ватта (15000 = 1500 Вт)
    cur_voltage     int    напряжение в ДЕСЯТЫХ долях вольта (2270 = 227 В)
    cur_current     int    ток в МИЛЛИАМПЕРАХ (6500 = 6,5 А)
    add_ele         int    накопленное потребление
    relay_status    str    поведение после сбоя питания ("last" / "on" / "off")
    child_lock      bool   блокировка кнопки
    fault           int    код неисправности, 0 = норма

Сервер уже выполняет пересчёт в нормальные единицы, поэтому API отдаёт
ватты, вольты и амперы в привычном виде.

=====================================================================
7. ЧТО МОЖЕТ ИЗМЕНИТЬСЯ В БУДУЩЕМ
=====================================================================

Рассматривается перепрошивка розетки на открытую прошивку
(Tasmota или OpenBeken) с переходом на собственный MQTT-брокер.
Это уберёт облако Tuya из цепочки полностью.

Для приложения это не должно ничего изменить: HTTP API останется
тем же, поменяется только внутренняя реализация сервера. Поэтому
приложению НЕ следует закладываться ни на какие детали Tuya —
работайте строго через описанные выше ручки.
